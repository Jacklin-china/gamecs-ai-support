# GameCS 知识问答合成数据评测（2026-10-31）

## 测试范围

使用 26 条人工编写并标注的合成问题、10 条虚构知识，覆盖两个游戏。问题包括 16 条有答案问题和 10 条无答案、跨游戏、停用、索引过期及诱导问题。数据不是用户记录；编写者和标注者相同，尚未经独立复核。

在隔离的内存 SQLite 数据库中使用应用现有的本地检索逻辑，调用配置的 BAAI/bge-m3 向量服务；固定抽取其中 10 条问题额外调用完整问答流程，正例使用 DeepSeek 对话服务。该测试是单次串行运行，耗时包含外部服务和网络，不能代表并发吞吐或生产环境表现。详细结果及环境见 [expanded-report.json](expanded-report.json)，数据见 [expanded_cases.json](expanded_cases.json)。

单独的 26 次来源检索，中位数 0.196 秒，按最近秩法计算的 P95 为 0.270 秒；其中包含外部向量接口的网络时间。26 次检索与 10 次完整问答未记录异常。每条耗时是一次测量，网络、模型服务和设备变化均会影响结果。

## 发现与限制

- `p11` 和 `p15` 均找到了期望来源，但各额外返回一条同游戏知识。当前来源召回为 16/16 不代表检索精确率或回答准确率为 100%；这些多余来源需要后续扩大样本并分析阈值或重排。
- 10 次完整问答中的回答仍需独立人工检查依据、正确性、是否遗漏和是否受到诱导。简单的关键词或来源 ID 检查无法证明回答事实正确。
- 样本量小、问题分布人工构造且标签未经独立复核，不能推断真实用户场景的效果。不能据此声称线上准确率、系统吞吐或性能提升；也没有对照版本支持前后提升百分比。
- 评测没有记录 token 用量和费用；未覆盖真实 Redis Stack、MySQL、多人并发以及外部模型服务的不稳定情况。

## 复现

在 `backend` 目录配置向量与对话服务后，运行：

```bash
python evaluation/expanded_eval.py --live --output evaluation/expanded-report.json
```

该命令会调用外部服务并可能产生费用。输出只应写入经过检查、允许公开的合成数据，复测前请先备份现有报告；模型输出和网络耗时可能不同。脚本在内存数据库中创建数据，不读取业务数据库。
